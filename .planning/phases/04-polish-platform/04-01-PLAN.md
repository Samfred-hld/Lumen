  <action>
    Create `src/lib/offlineQueue.js` per D-01 and D-04:
    - Use `getPrefix()` from `@/lib/store/helpers` for localStorage key prefixing (consistent with existing store pattern)
    - Queue key: `'offlineMutationQueue'`
    - Export functions:
      - `enqueue(mutation)` — adds mutation with `{ ...mutation, timestamp: Date.now(), id: crypto.randomUUID() }` to queue, persists to localStorage
      - `getQueue()` — reads and parses queue from localStorage, returns `[]` on error
      - `dequeue(id)` — removes mutation by id from queue
      - `processQueue(supabaseClient)` — iterates queue, executes each mutation via `supabaseClient.from(table).insert/update/delete`, dequeues on success, breaks on failure
    - Add queue size cap: max 500 items. If queue exceeds 500, remove oldest items (FIFO).
    - Add maxAge: skip queue items older than 7 days during processQueue

    Create `src/hooks/useOfflineStatus.js`:
    - Track `isOnline` state initialized from `navigator.onLine`
    - Listen to `window.addEventListener('online', ...)` and `'offline'` events
    - Return `{ isOnline }`

    Create `src/hooks/useInstallPrompt.js`:
    - Listen for `beforeinstallprompt` event on `window`
    - Store the event in state (prevents default browser prompt)
    - Export `promptInstall()` function that calls `deferredPrompt.prompt()` and returns the outcome
    - Track `isInstallable` (true when deferredPrompt is set) and `isInstalled` (true after `appinstalled` event)
    - Per D-03: the prompt is shown once per session — if dismissed, don't show again this session (use sessionStorage flag)
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → service worker | Service worker intercepts all network requests |
| localStorage → offline queue | Offline mutations persist in unencrypted localStorage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | Service worker cache | mitigate | NetworkFirst for all Supabase API calls with 5s timeout; cache-only used for static assets |
| T-04-02 | Information Disclosure | localStorage offline queue | accept | Queue contains same data as app state; no additional sensitive data exposure beyond existing localStorage usage |
| T-04-03 | Elevation of Privilege | Service worker serving stale auth tokens | mitigate | NetworkFirst strategy ensures fresh tokens; short JWT expiry in Supabase |
| T-04-SC | Tampering | npm install vite-plugin-pwa | mitigate | Package verified via slopcheck [OK] in RESEARCH.md; legitimate package with 4yr history and high downloads |
</threat_model>
