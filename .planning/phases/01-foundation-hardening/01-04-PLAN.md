Harden the error boundary to produce structured, grep-able crash logs (CONCERN #13):

1. **Update `componentDidCatch`** in ErrorBoundary.jsx:
   - Replace the existing `console.error('[Lúmen ErrorBoundary]', error, errorInfo)` with structured JSON logging:
   - Construct a crash payload object: `{ component: errorInfo?.componentStack?.split('\n')?.[0]?.trim() || 'Unknown', message: error?.message || 'Unknown error', stack: error?.stack || '', timestamp: new Date().toISOString(), userAgent: navigator.userAgent, url: window.location.href }`
   - Log it as: `console.error('[CRASH]', JSON.stringify(crashPayload))`
   - The `[CRASH]` prefix must be a literal string at the start of the log line for grep-ability
   - Also log a compact single-line fallback: `console.error('[CRASH]', error?.message, errorInfo?.componentStack?.split('\n')?.slice(0, 3)?.join(' → '))`

2. **Add a global `window.onerror` handler** as a separate module-level side effect (NOT inside the class — at the top level of the file, before the class definition):
   ```js
   // Register global error handler for uncaught errors outside React tree
   window.addEventListener('error', (event) => {
     const payload = {
       component: 'window.onerror',
       message: event.message || event.error?.message || 'Unknown error',
       stack: event.error?.stack || '',
       timestamp: new Date().toISOString(),
       url: window.location.href,
       userAgent: navigator.userAgent,
       source: event.filename || '',
       line: event.lineno || 0,
       col: event.colno || 0,
     };
     console.error('[CRASH]', JSON.stringify(payload));
   });
   ```
   - This catches errors that occur outside the React tree (event handlers, timers, async code)
   - The `[CRASH]` prefix must match exactly so both handlers produce grep-able output

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| console.error → browser console / log aggregator | Error data crosses from app code to external logging surface |
| git CLI → shell | bot-diff.js invokes git via child_process.execSync |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Information Disclosure | ErrorBoundary.jsx [CRASH] logging | mitigate | Logs include error message and stack trace but NO user data (no transaction values, no PII). componentStack may reveal internal file paths — acceptable for a client-side app (already visible in DevTools). |
| T-01-06 | Information Disclosure | window.onerror event handler | mitigate | Same as above — event.error.stack may contain file paths; no user financial data captured. |
| T-01-07 | Tampering | scripts/bot-diff.js child_process | accept | Invokes `git log` and `git diff` read-only — no writes, no destructive operations. Output is displayed to developer only. |
| T-01-08 | Denial of Service | npm audit network calls | accept | `npm audit` makes HTTP requests to the npm registry — inherent to the tool, not a vector we control. |
</threat_model>
